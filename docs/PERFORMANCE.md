# 0.1 资源占用与取舍

## 已实施

- 冻结版在导入 Qt 和通知模块前调用 multiprocessing.freeze_support()，采集子进程直接进入检测逻辑。打包自检验证子进程未导入 QtWidgets，并对空白帧运行 YOLOX、MediaPipe 和 ByteTrack。
- 收起到后台、打开设置或隐藏画面时，不解码 JPEG 为预览图；保留最新检测结果，返回时再恢复显示。
- 模型和安装器 SHA-256 使用分块读取，避免启动或打包时额外读入整个大文件。
- 帧队列仍只保留最新一帧；停止监测回收整个采集进程，空闲摄像头模式则保留模型以免反复加载。
- 打包排除未使用的训练/LLM 工具 JAX、TensorFlow、Torch 和开发测试工具；保留 Agg 绘图依赖入口，但不打包交互绘图库后端。原有未用 Qt PDF/QML DLL、视频文件 FFmpeg 后端排除规则继续生效。
- Inno Setup 改用 lzma2/ultra64；只影响下载体积和安装开销，不会降低安装后的运行内存。

## 2026-09-17 本机测量

Python 3.12、Windows x64；相同模型、640×480 空白画面、5 次推理。命令见 [诊断工具](../tools/README.md)。工作集是驻留物理内存；PrivateUsage 是私有提交量，不能直接当成物理内存。

| 隔离进程 | 工作集 MiB | 私有提交 MiB | 峰值工作集 MiB |
| --- | ---: | ---: | ---: |
| 检测 + 导入完整界面（旧子进程方式） | 510.4 | 1568.5 | 525.8 |
| 仅检测模块 | 454.5 | 1518.0 | 469.7 |

本次隔离测量减少约 56 MiB 工作集（约 11%）。不包含主面板进程，未测真实摄像头长时间运行、多人识别或其他机器的峰值，不能作为整机内存承诺。源码 Windows spawn 仍可能重新导入入口；上述提前分流针对发布安装版。

相同首次 0.1 构建内容：默认 LZMA2 安装器 193,056,196 字节；ultra64 为 189,594,019 字节，减少约 3.30 MiB（1.8%）。补齐许可证及自检代码后的本地最终安装器为 189,668,419 字节（约 180.88 MiB），展开文件约 522 MiB；CI 构建的最终大小以 Release 附件为准。旧目录中的 0.0.0 测试包使用不同模型和依赖，不能当作同功能基线比较。

安装后的主要体积：OpenCV 约 86 MiB、三个模型约 75 MiB、Qt 约 74 MiB、MediaPipe 约 64 MiB、SciPy 与其原生库约 67 MiB、NumPy 原生库约 36 MiB。安装包包含离线运行所需资源，仓库不包含这些二进制。

## 未采用与后续方向

- 本机把 OpenCV 线程数从默认 18 限为 2，加载模型加 5 帧推理耗时从约 1.48 秒增至 2.73 秒，内存差异不足 1 MiB，因此保留默认线程策略。
- SciPy 是 ByteTrack 分配等依赖链的一部分；MediaPipe 自带的 OpenCV DLL 与 Python 的 cv2 模块不是可直接互换的同一构建，不能按文件名相似就删除。
- requirements 中 JAX 为固定 MediaPipe 版本的声明依赖；源码环境继续保留以保证正常安装，发布包排除未调用的相关模块。两种 OpenCV 发行包来自上游依赖声明；当前还需要 contrib 的 SFace，不能直接替换为不含该接口的包。
- 如需明显进一步缩小包体积，应另行评估首次运行下载模型（牺牲离线安装）、更轻检测模型/量化（需重新评估远处人体与人脸召回）、更换跟踪依赖（增加维护范围）。0.1 不以降低检测能力换取表面体积下降。
